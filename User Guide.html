Parts · Products · Workers Analysis

Local web app · Windows user guide v50 · 2026-10🔒 100% local · no network · no uploads

In one sentence: an analysis web page that runs entirely on your computer. You enter or import products, parts (VC), workers, orders and the hour-report hour log; it calculates theoretical hours and gives you a Schedule (what to do next), a Retrospective (how the past went) and a theory vs actual comparison. All data stays in this computer's browser, and it works with the network unplugged.

1. Quick start

  1. Step 1 Copy the whole folder (e.g. from a USB drive) to a local disk on the Windows PC (such as drive D: or the Desktop).
  2. Step 2 Double-click Parts Analysis.exe.
  3. Step 3 If Windows shows the blue "Windows protected your PC" (SmartScreen) message, click "More info" → "Run anyway". Every small tool without a paid signing certificate gets this message; the program itself never goes online.
  4. Step 4 A small black window (the local server) appears and the browser opens http://localhost:4173. Keep the black window open while you work; close it when you're done. Your data is not lost.
💡 Nothing happens when you double-click the exe, or the browser doesn't open? Type http://localhost:4173 into the browser yourself. If that still doesn't work, use the fallback: double-click Start without exe.bat in the folder.

2. Where data is stored · backups

  • All data is saved in the browser's local storage (localStorage), tied to "this computer + this browser". The USB drive carries the program, not the data.
  • So switching computers, switching browsers (e.g. from Edge to Chrome) or clearing browser data means you won't see your old data. Make backups a habit.
  • How to back up: Import/Export tab → "Export full backup .json" downloads one JSON file. On a new computer, drop that JSON onto the import area to restore everything exactly (including all settings).
  • Always use the same browser and keep the address localhost:4173 (the exe and the fallback .bat use the same port, so they share data).
  • Data saved by the earlier Chinese version is converted automatically the first time you open this version.

3. The nine tabs

① Products

Register product names (e.g. Alpha, Beta). Product names become the columns of the worker ability table and the types referenced by orders.

② Parts (VC)

  • One VC (3-digit code) per row: difficulty (High/Low/None, decides who can do it) + repeat design hours t7 + first-order design hours t8.
  • At the top of the page is the check ratio setting: check hours = design hours × ratio (default 0.3; calibrating it from real data on the Hour Log tab is recommended).
  • parts.xlsx can be imported (column 1 = VC, column 8 = t7, column 9 = t8).

③ Workers

  • Two cells per person per product: design grade and check grade (A/B/C, blank = doesn't do it). A = can do High/Low/None, B = Low/None, C = None only. Grades only decide whether someone can do the work; hours come from the VC table.
  • At the bottom of the page are leave records: pick a person, enter start/end dates and leave hours per day (blank = full day). They only affect Schedule capacity, not Analysis or Retrospective.

④ Orders

  • One order per row: order no. + product + VC list + designer/checker + due date + created date + actual finish date.
  • Smart import: click "Import orders.xlsx" and give it the big sheet exported from the company system. The program finds the header row anywhere in the sheet, matches columns by keyword (Sales Order / Sales Order Item / Engineer VC / Designer / Checker / Product Series / BOM Required Date / Create On / Actual BOM Finish Date, etc. — English and Chinese headers both work) and shows a mapping dialog for you to check before importing.
  • Order no. = Sales Order + "-" + Item (leading zeros removed), e.g. 123456789-1200; every table and export uses it to identify orders.
  • The actual finish date is the dividing line: filled in = completed → goes to the Retrospective; blank = unfinished → goes to the Schedule.

⑤ Import/Export

The drop area recognizes parts / workers / orders / HourReport files automatically; you can export Excel files; full backup/restore is here too.

⑥ Analysis — theoretical hours vs actual logged hours

  • Theoretical hours summary: design/check theoretical hours of all orders from the VC table, team daily capacity, and how many workdays the whole team needs.
  • Theory vs actual (everyone): once an hour log is imported, compares theory / actual / difference / ratio for each stage.
  • Per worker theory vs actual: theoretical hours of each person's assigned orders vs hours actually logged.
  • Order hours detail: VC count, coefficient and the source of design/check hours for every order.

⑦ Schedule — only unfinished orders, starting today

  • Three methods, each giving every order an expected start/finish date and days early/late (designer/checker shown on every row):
    ① Sequential: ignores due dates, queues by created date, finishes one then starts the next;
    ② By due date (slot): earliest due first; when work finishes early, later tasks fill the free time automatically;
    ③ Close to due date (reference): starts as late as possible and finishes N workdays before the due date (adjustable buffer).
  • Capacity = people × hours per person per day, minus spread-out annual leave (configurable) and exact leave records; only Monday–Friday count as workdays.
  • ④ Per worker · personal schedule: each person's own timeline — design hours go to the designer, check goes to the checker after that order's design is done. The dropdown switches between the three methods. The summary table lists each person's orders, total hours, earliest start and busy-until date; pick a worker to see a day-by-day progress bar and the orders handled each day.
  • ⑤ Reassignment suggestions: suggests moving work from overloaded workers to less busy ones — by grade where grades exist (never someone whose grade can't do it); when no graded candidate fits, "whoever is free", flagged "ability not filled". Design only moves to designers, check only to checkers; many small orders are bundled and moved to the same person. These are suggestions only and never change your data.
  • Long tables can be collapsed: sections over 30 rows start collapsed (on both Schedule and Retrospective). Click a section title to expand/collapse; "Expand all / Collapse all" buttons are at the top. Collapsing doesn't affect exports.
  • Automatic warnings: overdue orders whose due date has passed, and suspiciously distant due dates (e.g. 2027) that look like typos.
  • "Export report" contains the full daily timeline, both full per-order tables, per-person daily load (for the method currently selected on the page) and the full reassignment list (not limited by how many rows the page shows).

⑧ Retrospective — completed orders only (earliest created date → today)

  • Actual delivery performance: on-time rate, number of late orders, median/longest delay (each measured against that order's own due date).
  • Completion speed: half of orders ≤ X workdays, 90% ≤ Y days, the slowest 5%, plus a distribution bar.
  • Load per worker: actual logged hours ÷ available hours per year ((260 − annual leave) × hours per person per day); over 100% is red.
  • Standard vs actual hours: each person's efficiency = standard ÷ actual (>100% means faster than standard).

⑨ Hour Log — hour-report integration

  • Import HourReport_{year}_Analysis.xlsx exported from hour-report (drop it on the Import tab or use the button on the Hour Log tab; detected by the Data (long) sheet).
  • See each person's hours for the year: order design/check, overtime, leave, utilization, order hours per day.
  • 📐 Actual-hours basis (important): one click replaces three settings with real values — hours per person per day (average hours actually spent on orders per day), check ratio (actual check ÷ design), and schedule annual leave set to zero (real data already includes leave). After that, Analysis / Schedule / Retrospective all follow the real pace. Strongly recommended once you've imported an hour log.

4. Calculation rules

RuleDetails
Design hoursΣ(hours of each VC in the order) × quantity coefficient: ≤5 VCs ×1, 6–10 ×1.2, >10 ×1.5
First vs repeatFor the same "product + VC", the order with the earliest created date uses t8 (first order); later ones use t7
Special valuesHours of 0 → counted as 0.03h; VC 999 → fixed 0.08h
Check hoursDesign × check ratio (default 0.3, can be calibrated from the hour log)
Void ordersOrders whose designer/checker is null / special order / order canceled are excluded entirely
WorkdaysMonday–Friday only; annual leave is spread over 260 workdays per year as a capacity discount
Order no.Sales Order + "-" + Item (leading zeros removed), e.g. 123456789-1200
Completed / openDecided by whether "Actual finish date" is filled in: open → Schedule, completed → Retrospective

5. Recommended workflow

  1. First time: import the big order sheet (smart import on the Orders tab) → import parts.xlsx → import the HourReport log → click "Apply actual basis" on the Hour Log tab → look at Analysis / Schedule / Retrospective in turn.
  2. Daily / monthly: re-import the latest order sheet and hour log (replace mode) → re-run the three tabs.
  3. As you go: after any big change, make a full backup on the Import/Export tab.

6. Blue/orange reconciliation colors

The worker roster (Workers tab) and the hour log are matched by exact name. If the spelling differs (e.g. the roster says Sam and the hour log uses a Chinese name), they won't link up, and the program marks it with color:

  • 🔵 Blue On the roster but not in the hour log — either they really logged nothing, or the names are spelled differently;
  • 🟠 Orange Logged hours in the hour log but not on the roster.

If you see lots of blue/orange, change the names on one side to match and they'll link up automatically (the two colored notes at the top of the Hour Log tab list the exact names).

7. FAQ

QuestionAnswer
Windows blocks the exeSmartScreen warns about every small tool without a paid signature. Click "More info" → "Run anyway". The program doesn't go online — you can disconnect the network first to check.
Will closing the black window lose data?No. Data lives in the browser; the black window is only the local server. Double-click the exe next time and carry on.
The browser didn't openGo to http://localhost:4173 yourself, or use Start without exe.bat.
My data suddenly "disappeared"Most likely a different browser, a different address (e.g. 127.0.0.1 vs localhost) or cleared browser data. Go back to the original browser + localhost:4173; if it's gone, restore from your full backup JSON.
The schedule shows a year far in the past/futureThe timeline ends at the latest due date. The program names the orders whose due date is more than a year after the latest created date (likely typos); search for that year on the Orders tab and fix it.
Someone shows 0 hours (blue) in the RetrospectiveIt doesn't mean they did nothing — it's a name-matching issue or no hours were logged, see the previous section.
Does it upload our data?No. The exe only listens on this computer (127.0.0.1), all calculations run in the browser, and Excel is parsed with a bundled library. It works fully offline.
Can several people use it at once?It's a single-computer tool. To share results, send the Excel from each tab's "Export report .xlsx".
